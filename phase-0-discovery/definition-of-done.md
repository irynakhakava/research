# Definition of Done — MVP

Связанный туториал: [Шаг 4](../docs/tutorials/00-discovery.md#шаг-4-definition-of-done-mvp)

MVP считается готовым, когда выполнены **все** критерии ниже (или явно waived с причиной).

## Продуктовые критерии

| # | Критерий | Порог | Проверка |
|---|----------|-------|----------|
| 1 | Поиск находит нужный документ | Recall@10 ≥ 0.70 на gold-set | offline eval |
| 2 | Ранжирование | MRR ≥ 0.50 на gold-set | offline eval |
| 3 | Ответ опирается на источники | ≥ 80% `/ask` с корректными цитатами (human или LLM-judge) | eval sample ≥ 50 |
| 4 | Отказ при отсутствии знаний | ≥ 90% refuse-кейсов дают refuse / nearest links без выдуманных фактов | gold-set subset |
| 5 | Пользователь видит источники | каждый ответ содержит `citations[]` с url/path | contract test |

## Инженерные критерии

| # | Критерий | Проверка |
|---|----------|----------|
| 6 | Индексируются все источники `priority: p0` | сверка с `sources.catalog.yaml` |
| 7 | ACL-фильтр не пропускает чужие чанки | negative tests |
| 8 | NFR latency `/ask` | p95 в пределах `nfr.md` на staging нагрузке |
| 9 | Пересборка индекса из `data/corpus` документирована и запускается одной командой/job'ом | runbook + dry-run |
| 10 | Есть eval-команда в CI (хотя бы smoke на 10 кейсах) | CI green |

## Out of scope MVP (явно не делаем)

- Долгий диалог с памятью / multi-turn agent  
- Автоматическая правка Confluence  
- Fine-tune LLM «с нуля» (допустим только выбор/сравнение готовых моделей)  
- Индексация тикетов Jira/Slack history  
- UI-портал (достаточно API + простой клиент/Swagger)
