# ADR-0001 · Scope MVP поиска по документации

- **Статус:** accepted  
- **Дата:** 2026-07-22  
- **Связанный туториал:** [Шаг 6](../docs/tutorials/00-discovery.md#шаг-6-короткий-adr-решение)

## Контекст

Нужен микросервис поиска по документации команд с RAG. Реальные корпоративные вики/репозитории в этом проекте **не используются**.

## Решение

1. **Только статические данные.** Индексируем и ищем исключительно по `data/corpus/**/*.md`. Коннекторы к Confluence/Notion/Git/Drive **не строим**.  
2. **Каталог источников** (`sources.catalog.yaml`) — модель метаданных демо-орг. NordLedger (priority, ACL, owner). Поля `location` / `ingest` — справочные, не runtime.  
3. **Источники для индекса MVP** — документы, у которых `source_id` в каталоге имеет `priority: p0` (файлы уже лежат в `data/corpus/<source_id>/`).  
4. **Режим индекса** — один логический индекс с фильтрацией по metadata (`team`, `space`, `acl_tags`).  
5. **Языки** — русский как основной для запросов; документы ru/en.  
6. **API** — `/search` и `/ask` (retrieve + LLM с цитатами).  
7. **Политика незнания** — `refuse_with_nearest_links` (см. `nfr.md`).  
8. **Эксперименты** — на том же статическом корпусе и gold-set (фаза 4).

## Альтернативы и почему отклонены

| Альтернатива | Почему нет |
|--------------|------------|
| Живые коннекторы к вики/git | Вне scope; всё на статике |
| Индексировать «всю вики» | Нет реальной вики; шум даже в демо |
| Только keyword search без векторов | Не соответствует цели проекта |
| Отдельный индекс на команду | Лишняя сложность без нужды |

## Последствия

- Фаза 1 = чтение/чанкинг/метаданные из `data/corpus` + `manifest.json`, **без** sync/webhooks.  
- Freshness NFR = актуальность файлов в git-репозитории проекта, не lag внешнего API.  
- Новые знания добавляются новым `.md` + записью в catalog/gold-set, не коннектором.  
- p1-документы в корпусе могут лежать на диске, но в MVP-индекс не обязательны.
