# Таксономия пользовательских запросов

Связанный туториал: [Шаг 2 · Таксономия запросов](../docs/tutorials/00-discovery.md#шаг-2-таксономия-запросов)

## Фокус MVP

| Поле | Значение |
|------|----------|
| Доминирующий тип для первой оптимизации | `how-to` |
| Второй по важности | `troubleshooting` |
| Язык запросов | ru (допускаются смешанные ru/en термины) |

> Замените фокус после интервью с дежурными/владельцами доков.

---

## Типы запросов

### 1. `how-to` — как сделать

Пользователь хочет пошаговую инструкцию.

**Примеры формулировок (замените на свои):**

- Как задеплоить сервис payments в staging?
- Как добавить нового члена в on-call ротацию?
- Как выписать сертификат для внутреннего сервиса?

**Что должно находиться:** runbooks, гайды, разделы «Procedure» / «Steps».

---

### 2. `troubleshooting` — что сломалось

Есть симптом, ошибка, алерт.

**Примеры:**

- Prometheus орёт `KubePodCrashLooping` на payments — что проверить первым?
- Получаю 403 от API gateway после ротации ключей, куда смотреть?
- Почему миграция liquibase зависла на lock?

**Что должно находиться:** разделы Incident / FAQ / known issues, иногда how-to с rollback.

---

### 3. `where-is` — где лежит / кто владелец

Нужен указатель, а не инструкция.

**Примеры:**

- Где репозиторий сервиса billing-workers?
- Кто owner документации по Kafka в нашей орг-е?
- В каком Confluence space лежат runbooks платформы?

**Что должно находиться:** overview-страницы, README с ссылками, каталоги сервисов.

---

### 4. `concept` — что это значит

Нужно объяснение термина или архитектуры.

**Примеры:**

- Что такое наш internal service mesh и зачем sidecars?
- Чем staging отличается от preprod у нас?

**Что должно находиться:** architecture overview, glossaries, ADRs.

---

### 5. `policy` — можно / нельзя / как правильно по правилам

**Примеры:**

- Можно ли хранить PII в логах staging?
- Какой SLA на восстановление после инцидента Sev-1?

**Что должно находиться:** policy-страницы, security guidelines. Часто `p1` для MVP.

---

### 6. `refuse` — в документации ответа нет

Не отдельный «тип вопроса пользователя», а **ожидаемое поведение системы**.  
В gold-set помечается `expected_behavior: refuse`.

**Примеры:**

- Какой пароль от прод-БД payments? (секреты не должны быть в доках / не выдаём)
- Когда Иванов выйдет из отпуска? (не документация)

## Покрытие (заполните по мере сбора gold-set)

| query_type | Целевая доля в gold-set | Факт (шт. / из 36) |
|------------|-------------------------|---------------------|
| how-to | 40% | 14 (~39%) |
| troubleshooting | 30% | 7 (~19%) |
| where-is | 15% | 5 (~14%) |
| concept | 10% | 7 (~19%) |
| policy | 5% | 3 (~8%) |
| refuse-кейсы | ≥3 шт. для demo | 3 |
